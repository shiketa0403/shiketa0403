# バッチ記事作成手順書（スプシ連携）

「**バッチから次のN件作成して**」と指示されたらこの手順書に従う。
記事1本ごとの作り方は `wp-article/WORKFLOW.md` が正で、本書はその外側のループ
（スプシ読取 → 対象行の選定 → 作成 → 書き戻し）と**バッチ限定ルール**を定める。

## 0. バッチ設定の読み込み

`wp-article/config/batch_lovedoll.json` を読む（バッチ名の指定がなければこれが既定）。
以降、spreadsheet_id / site_key / article_type / ad_tag 等はこの設定に従う。

## 1. スプシの読み取り

1. Googleスプレッドシート（spreadsheet_id）を開く
2. **対象シートは sheet_hint の条件で特定する**（列に「国」「素材」がある方のシート）。
   1枚目（代理店・通販サイト一覧）は対象外
3. 右端に「**作成状況**」「**下書きURL**」列が無ければ追加する（1回だけ）

## 2. 対象行の選定

上から順に見て、次を**すべて満たす行**を未作成対象とし、指示された件数だけ選ぶ:
- 作成可否が「〇」**ではない**（〇の行は作成しない・スキップ）
- 作成状況が空欄（「済」「スキップ〜」の行は飛ばす）

## 3. 1行 → 1記事の作成

各行について、WORKFLOW.md の通常フロー（Phase 0〜11）を実行する。案件情報の組み立て:

| 項目 | 値 |
|---|---|
| キーワード | シートの「キーワード」列そのまま |
| 案件名（サービス名） | 同上（ブランド名） |
| 公式サイトURL | 「商標」列のURL。**空欄ならリサーチで公式サイトを特定**（特定できなければこの行をスキップし作成状況に「スキップ:公式サイト不明」と記録して次の行へ） |
| 記事タイプ | 設定の article_type（商標ライト） |
| 投稿先サイト | 設定の site_key（lovedoll） |
| メディア情報 | 設定の media_info |
| スラッグ | ブランド名の英小文字ハイフン（例: WM Doll → wm-doll） |
| アフィリエイトリンク | なし（シート2は全行なし） |
| 補足材料 | 「備考」「メモ」「国」「素材」列の内容を facts.json の初期材料として渡す（出典確認は通常通り行う） |

### バッチ限定ルール（このバッチの記事だけに適用・通常記事には適用しない）

広告タグ `ad_tag`（`[st_af id="66"]`）を次の2箇所に挿入する:
1. **アフィリエイト明示ブロック（st-cmemo）の直下**
2. **まとめ文末のCTAボタンの直後**（記事の最後）

このルールは meta.json に `"batch": "lovedoll_brands", "ad_tag": "[st_af id=\"66\"]"` として
記録し、組立（Phase 10）で適用する。

## 4. スプシへの書き戻し

1記事の下書き投稿が完了するたびに（まとめて最後ではなく都度）:
- 作成状況 → 「済」
- 下書きURL → publish_result.json の下書きURL

失敗・スキップ時:
- 作成状況 → 「スキップ:理由」（例: スキップ:公式サイト不明、スキップ:投稿エラー）
- 途中失敗でもバッチは止めず、次の行へ進む

## 5. 完了報告

指示された件数を処理したら、次を報告して終了:
- 作成した記事の一覧（キーワード / 下書きURL）
- スキップした行と理由
- スプシ上の残り対象行数の目安

## 注意

- 1回の指示で作るのは指示された件数だけ。勝手に続けない
- 同じ行を二重に作らない（作成状況列が防波堤。書き戻しを絶対に忘れない）
- Cloudflare等でスクショが取れないサイトは通常ルール通りスクショなしで作成
- スプシの既存列（キーワード〜メモ、国、素材）は編集しない。書き込むのは追加した2列のみ
